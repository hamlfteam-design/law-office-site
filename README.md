# موقع مؤسسة د. حسن عبد المنعم حسن

موقع متعدد الصفحات (HTML/CSS/JS بسيط، بدون أي سيرفر backend) — تقدر تستضيفه مجانًا على GitHub Pages.
مبني على أساس أولويات "الخطة التسويقية الشاملة": صفحة رئيسية + صفحة هبوط مستقلة لكل خدمة رئيسية
(بدل صفحة "خدماتنا" واحدة عامة) + صفحة إنجليزية كاملة للعملاء الأجانب والعرب — وهي بالظبط القناة اللي
الخطة وصفتها بأنها "أضعف حلقة رغم إنها لازم تكون الأقوى".

## هيكل الموقع

- `index.html` — الصفحة الرئيسية (من نحن، الفريق، الوسائط، تواصل معنا)
- `services/naqd.html` — الطعن بالنقض
- `services/corporate.html` — الاشتراك القانوني الشهري للشركات
- `services/foreign-judgments.html` — تنفيذ الأحكام الأجنبية
- `services/poa-abroad.html` — التوكيل من الخارج
- `services/inheritance.html` — المواريث وقسمة التركات
- `en/index.html` — الصفحة الإنجليزية الأم للعملاء الأجانب والعرب (Foreign & Arab Clients)
- `portal/` — بوابة الموكلين (تسجيل دخول + عرض القضايا والجلسات والمستندات) — شغالة بالكامل من المتصفح
  عبر Firebase (Auth + Firestore)، تفاصيلها في قسم "بوابة الموكلين" تحت.

كل صفحات الخدمات مبنية من نفس النصوص والأسئلة الموجودة في ملفات الخطة (بنك الأسئلة وسكريبتات
الفيديو)، فمفيش تكرار جهد — نفس المحتوى المخطط له للفيسبوك اتحول لصفحات هبوط دائمة على الموقع
بدل منشورات بتموت في يومين.

كمان مضاف Schema.org LegalService markup في `index.html` (وسم بيانات منظمة) بالاسم والعنوان
والساعات وقائمة `sameAs` — وده تحديدًا اللي الخطة وصفته في "الباب الرابع عشر" كأرخص بند وأعلاه أثرًا
لربط كيان المؤسسة في نتائج البحث. لازم تضيف فيه روابط فيسبوك ولينكدإن وبطاقة جوجل الحقيقية أول ما تتوفر.

## التعديلات المتبقية

1. **الخطوط (مهم)**
   - الموقع حالياً شغال بخط Cairo من Google Fonts، لأن معايا مش موجود ملفات الخط المعتمد فعلياً
     في الهوية البصرية: **SF Sultan** (للعناوين) و **SF-Mada** (للنصوص) — شايفهم متضمّنين في
     معاينة "حسابات العميل" بصيغة `.ttf`.
   - لو تبعتلي ملفات `Sultan-bold.ttf` و `sf-mada-bold.ttf` (أو أي أوزان تانية عندك)، أضيفهم
     كـ `@font-face` في `css/style.css` بدل Cairo، والموقع كله هياخد شكل الهوية الحقيقية.

2. **بيانات لسه ناقصة**
   - أسماء وصور باقي أعضاء الفريق غير د. حسن (قسم `team` في `index.html`)
   - روابط الصور/الملفات في قسم `media`
   - أسعار وسقوف باقات الاشتراك القانوني الأربعة (`services/corporate.html`) — موجودة بالتفصيل في
     "الباب السادس عشر" من الخطة التسويقية، ماحطيتهاش لأن الوثيقة نفسها بتقول إنها تُراجَع كل 6 شهور
     وتُعرض على المحاسب القانوني قبل النشر، وكمان القرار المسجّل في معاينة صفحة الفيسبوك إنها
     "لا تُنشر قبل وجود عقد الاشتراك" — حطيت بدالها نفس الصياغة المؤقتة المعتمدة (تُحدَّد بعد جلسة تقدير احتياج)
   - بريد الدومين info@hamlf.com لسه مش مُنشأ؛ الموقع حالياً بيستخدم info.hamlf@gmail.com كبديل مؤقت

3. **الملفات (صور، PDF، صوتيات)**
   - حط صورك في: `assets/images/`
   - حط ملفات PDF والتسجيلات الصوتية في: `assets/files/`
   - عدّل الروابط في `index.html` (قسم `media`) بنفس أسماء الملفات اللي رفعتها

4. **نموذج التواصل**
   - النموذج الحالي شكلي فقط ولا يرسل فعليًا (الموقع static بدون سيرفر). لو عايز يشتغل فعليًا:
     - اعمل حساب مجاني على [Formspree](https://formspree.io) أو خدمة مشابهة
     - غيّر سطر `<form class="contact-form" onsubmit="return false;">` إلى الرابط اللي هتاخده منهم
     - أو ببساطة سيب فقط أرقام التواصل المباشرة (هاتف/واتساب/فيسبوك) بدون فورم

## بوابة الموكلين (portal/)

بوابة كاملة تشتغل من غير أي سيرفر — كل المنطق شغال في المتصفح عبر Firebase (Auth + Firestore)،
فتقدر تفضل مستضاف مجاناً على GitHub Pages بالظبط زي باقي الموقع.

**الفكرة**: الموكل يدخل إيميله (لازم يكون نفسه المسجّل في قاعدة بياناتك ضمن كولكشن `clients`، حقل
`matchEmails`) → النظام يتأكد إن الإيميل ده موكل فعلي → لو أول مرة، يختار كلمة سر لنفسه على طول (بدل
الـ email link اللي Firebase بتقفله)؛ لو عنده حساب بالفعل، يدخل بكلمة السر العادية. بعد الدخول، بيشوف
قضاياه بس (اللي فيها `clientUids` شايلة الـ uid بتاعه) ومواعيد جلساتها.

⚠️ **مهم تعرفه**: الربط بين الموكل وقضاياه بيتم عبر حقل `clientUids` على وثيقة القضية، وده بيتحدّث
تلقائياً من تطبيق المكتب (com.sherif.lawyer) كل 6 ساعات — مش فوري. يعني لو موكل سجّل دخول للمرة الأولى
في البوابة، ممكن ياخد لحد 6 ساعات لحد ما قضاياه تظهرله (لو التطبيق مفتوح ومتصل بالنت على جهاز في المكتب).
القضايا القديمة اللي اتسجلت قبل إضافة الحقل ده هتاخد نفس المدة عشان تتحدّث.

**الملفات:**
- `portal/index.html` — صفحة الدخول والتفعيل
- `portal/dashboard.html` — صفحة "قضاياي" بعد الدخول
- `portal/portal-config.js` — **الملف الوحيد اللي محتاج تعدّله** لربط البوابة بمشروع Firebase (✅ متظبط بالفعل ببيانات مشروع "Profissional Lawyer updat")

**حالة التفعيل الحالية:**

1. ✅ مشروع Firebase الحقيقي موصّل (`profissional-lawyer-updat`) وبيانات `firebaseConfig` متحطة في `portal-config.js`.
2. ✅ **Email/Password** مفعّل من Authentication → Sign-in method.
3. ✅ **متزبط ومؤكَّد**: البوابة بتقرأ من نفس الـ schema الحقيقي اللي تطبيق "المحامي المحترف" بيستخدمه
   فعلاً (اتأكد مباشرة بفتح الوثائق الحقيقية في Firestore Console):
   ```
   offices/{officeId}/records/clients/items/{itemId}
   offices/{officeId}/records/cases/items/{itemId}
   ```
   كل وثيقة موكل فيها `matchEmails` (مصفوفة إيميلات مسموح لها تربط نفسها بالسجل — ده اللي التطبيق
   بيدخله يدوياً وقت فتح ملف الموكل) و `clientUid` (فاضي لحد ما الموكل يعمل أول تسجيل دخول من البوابة،
   وقتها البوابة بتسجّله تلقائياً).
   كل وثيقة قضية فيها حقل `clientUids` (array من auth uid) على مستوى المستند نفسه — ده اللي البوابة
   بتفلتر بيه (`array-contains`)، وبيتحدّث تلقائياً من تطبيق المكتب كل 6 ساعات. باقي بيانات القضية
   (رقم الملف، الموضوع، المحكمة، الحالة، الجلسات...) متخزّنة جوه حقل نصي واحد اسمه `json`
   (`JSON.parse` مطلوب) — مفيش كولكشن جلسات منفصل، الجلسات `array` جوه نفس وثيقة القضية.
4. ⏳ **ناقص**: في **Firestore Database → Rules**، لازم تتأكد إن كل موكل يقدر يقرأ بيانات قضاياه هو بس،
   وإن كولكشن الموكلين مقروء بس (علشان خطوة `matchEmails` تشتغل قبل تسجيل الدخول)، مع سماح تحديد واحد بس
   لحقل `clientUid` (خطوة "ربط الحساب" أول مرة):
   ```
   match /offices/{officeId}/records/clients/items/{itemId} {
     allow read: if true;
     allow update: if request.auth != null
       && request.auth.token.email in resource.data.matchEmails
       && resource.data.clientUid == null
       && request.resource.data.diff(resource.data).affectedKeys().hasOnly(["clientUid"])
       && request.resource.data.clientUid == request.auth.uid;
     allow create, delete: if false; // تتعدل من الكونسول يدوياً بس (أو من تطبيق المكتب)
   }
   match /offices/{officeId}/records/cases/items/{itemId} {
     allow read: if request.auth != null
       && (resource.data.clientUids is list)
       && (request.auth.uid in resource.data.clientUids);
     allow write: if false; // القضايا بتتحدّث من تطبيق المكتب بس، مش من البوابة
   }
   ```
5. لو عايز إضافة تلقائية لمواعيد الجلسات في Google Calendar بتاع الموكل (بالإضافة لعرضها في البوابة)،
   ده محتاج خطوة تكامل إضافية (Google Calendar API) هنضيفها بعد ما تستقر البوابة الأساسية.

**مهم — خلّي ملفات PDF المرفوعة للموكلين خفيفة:**
ملف PDF كبير (فيه صفحات ماسحة ضوئية بدقة عالية مثلاً) بياخد وقت طويل يفتح للموكل وبيستهلك مساحة تخزين
على Firebase من غير داعٍ. قبل ما ترفع أي مستند لقضية موكل:
- لو الملف ماسكانر (سكانر مستندات)، اعمل ضغط له الأول (فيه أدوات مجانية أونلاين، أو اطلب مني أعمل
  الضغط لو بعتّلي الملفات هنا).
- الهدف: ملف الصفحة الواحدة الممسوحة ضوئياً يكون حوالي 100–300 KB بدل ميجا كاملة، من غير ما تفقد وضوح النص.
- سجّل حجم الملف بالـ KB في حقل `sizeKB` وقت رفعه (البوابة بتعرضه للموكل جنب اسم الملف).

## طريقة النشر على GitHub Pages (خطوة بخطوة)

1. اعمل حساب على [github.com](https://github.com) لو مفيش عندك واحد.
2. اعمل Repository جديد (مثلاً باسم `law-office-site`) — خليه **Public**.
3. ارفع كل ملفات هذا المجلد (`index.html`, `css/`, `js/`, `assets/`) في الـ repo. أسهل طريقة:
   - من صفحة الـ repo، دوس **Add file → Upload files**
   - اسحب كل الملفات والمجلدات وارفعها، ثم **Commit changes**
4. روح لإعدادات الـ repo: **Settings → Pages**
5. تحت **Build and deployment → Source** اختار **Deploy from a branch**
6. اختار الـ Branch: **main** والمجلد: **/ (root)** ثم **Save**
7. استنى دقيقة أو اتنين، هيظهرلك رابط الموقع في نفس الصفحة على شكل:
   `https://<اسم-حسابك>.github.io/law-office-site/`

بعد كده أي تعديل تعمله وترفعه (Commit) على نفس الـ repo هيتحدث في الموقع تلقائيًا خلال دقايق.

## ربط دومين مخصص (اختياري)

لو عايز اسم دومين خاص بيك (مثلاً `www.mylawoffice.com`) بدل رابط github.io:
- اشتري الدومين من أي موفر (Namecheap, GoDaddy, إلخ)
- في **Settings → Pages → Custom domain** بتاع الـ repo، حط اسم الدومين
- اعمل إعدادات DNS عند موفر الدومين تشاور على GitHub Pages (GitHub بيوضحلك القيم بالظبط بعد ما تكتب الدومين)
